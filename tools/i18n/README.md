# Notes RC1 i18n | canonical first-party tooling

**CONTENT HOLD**: the Notes repository does not yet contain six reviewed locale PO catalogs.
English is the source language; required locales: nl_NL, de_DE, fr_FR, es_ES, it_IT, pt_PT.

The tools reuse the pinned canonical Core Blueprint i18n engine 1.1.0 from Bookings without changes.
Environment: Python 3, WP-CLI wp i18n commands, gettext msgmerge, msgattrib, msgfmt, Git.

Read-only validation: python3 tools/i18n/check-reference ; bash tools/i18n/check
Mutating operator-only synchronization: bash tools/i18n/update

The update command requires the six existing reviewed PO sources and refuses missing catalogs.
The check command refuses stale, fuzzy and untranslated strings. No live translation service is used.
Do not create empty catalogs or substitute English copies as approved translation evidence.
Source POT must come from current PHP and JavaScript using WP-CLI make-pot.
Generate JS translation JSON using WP-CLI make-json only from reviewed PO sources.
Customer packaging and browser runtime acceptance remain blocked until catalog review and tests.
The Alpha26 ZIP remains an internal fixture, never an accepted release.

### Review-only source extraction

Run `bash tools/i18n/prepare-review` on the operator workstation. It uses the
pinned WordPress-aware `catalog.generate_pot` to extract PHP and JavaScript into
`dist/i18n-review/core-blueprint-notes.pot`. This is **not** the approved catalog,
and does not satisfy `tools/i18n/check`.

Translate and review the six required locales, then use the canonical update/check
workflow. Missing or unreviewed POs remain a customer-release content hold.

### Generated files and clean checkout

The repository ignores \`dist/\` and Python \`__pycache__/\` artifacts. Existing
\`tools/i18n/__pycache__/\` is harmless generated bytecode from the earlier run;
it is ignored and is not deleted by the tooling. No operator cleanup is needed.
The wrapper commands disable future Python bytecode writes. Reviewed catalogs
must be deliberately placed in \`languages/\` and committed as translation source,
not copied unreviewed from \`dist/i18n-review/\`.

### Unreviewed PO preparation (six locales)

After source extraction, run `bash tools/i18n/prepare-drafts`. This invokes gettext
`msginit --no-translator` for nl_NL, de_DE, fr_FR, es_ES, it_IT and pt_PT,
checks that their message IDs exactly match the current POT, and refuses any
automatically prefilled translation. Drafts are stored exclusively under
`dist/i18n-review/drafts/` with an `UNREVIEWED` manifest.

Re-running with an unchanged POT preserves any existing editorial progress.
If the POT changes, it fails rather than overwriting drafts; reconcile with the
canonical `msgmerge` flow after review. Nothing is copied into `languages/`
automatically, and customer packaging remains blocked until the six POs are
reviewed and accepted through the canonical check.

### Full six-locale WordPress runtime candidate (305 messages)

Get the pinned `core-blueprint-notes-rc1-i18n-candidate.zip` archive.
`bash tools/i18n/import-candidate <zip>` verifies its SHA-256, regenerates a
fresh POT from GitHub source via WP-CLI, checks all 305 keys, validates all six
POs via gettext and refuses overwriting existing `languages/`.
`bash tools/build-localized-candidate --execute` runs full Level 1/2 local
regressions, checks POT/PO, produces six MO and 30 WP JavaScript JSON
files, then builds and independently verifies a reproducible installable
i18n **test-only** ZIP and its checksum.

The source branch and code changes remain separate from the green Alpha26
hardening baseline. No AI-generated catalog can be called independently
editorially approved by these automated checks. The customer release gate
remains blocked pending owner acceptance.
